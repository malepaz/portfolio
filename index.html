  • Oct 20, 2026

    Fixing a broken PATH after editing .bashrc NEW!

    I added a line to .bashrc, typed PATH=/my/new/dir instead of PATH="$PATH:/my/new/dir", and suddenly ls did not exist. Lesson: always append, and keep a terminal open while testing. /usr/bin/nano with the full path saved me.

    What actually happened: PATH=/my/new/dir replaced the whole variable, so the shell could only find programs inside that one directory. Every new terminal sourced the broken .bashrc, which is why it felt like the whole system was gone. It was not; only the map to it was.

    The fix was boring, which is the best kind: open the file by its absolute path (/usr/bin/nano ~/.bashrc), change the line to export PATH="$PATH:/my/new/dir", then source ~/.bashrc in the terminal I had kept open. Now I test every .bashrc change in a second terminal before closing the first one.

    Current mood: relieved · ·

  • Oct 8, 2026

    What I learned setting up SSH keys

    Generated an ed25519 key, copied it with ssh-copy-id, then turned off password login in sshd_config. The scary part was restarting sshd while connected. The useful part was learning that ~/.ssh permissions really do matter (700 for the dir, 600 for the keys).

    Steps, for future me: ssh-keygen -t ed25519 -C "malena@lab", then ssh-copy-id -i ~/.ssh/id_ed25519.pub malena@10.0.0.5, then log in once with the key to be sure it works before touching sshd_config.

    In /etc/ssh/sshd_config I set PasswordAuthentication no, PermitRootLogin no and a non-default port, ran sudo sshd -t to check the syntax, and only then sudo systemctl restart sshd, with a second session already open as a safety net. fail2ban went in the same evening after I looked at auth.log and saw how many strangers had tried the password route.

    Current mood: careful · ·

  • Sep 25, 2026

    First GitHub Actions deploy

    Pushed to main, watched the workflow go green, and this page was live on Cloudflare Workers a minute later. I then added a curl smoke test because "green" and "actually online" are not the same thing. First real DevOps feeling!

    The workflow is small: on push to main, npm ci, npm run build, npx wrangler deploy. The Cloudflare token comes from 1Password as an op:// reference, loaded at run time, so the repo has no secrets and I can rotate the token without touching git.

    The smoke test is one line: curl -fsS https://malena.example | grep -q "Malena". The first time I wrote it, it failed because the page was cached and still showed the old title. That was the point: the check caught something the green deploy step did not.

    Current mood: accomplished · ·

This Site as a Project

This page isn't just a profile — it's my first real DevOps project. Here's how it's built and shipped:

FrameworkAstro, building to plain static HTML/CSS (fast and boring, which I like).
HostingCloudflare Workers serving static assets, deployed with wrangler.
CI/CDGitHub Actions, triggered on every push to main.
Secrets1Password: the workflow reads op:// references at run time, so there are no secrets in the repo, ever.
Smoke testAfter deploy, a curl checks the live URL returns 200 and contains my name. If not, the job fails loudly.

Pipeline on push to main:

  1. git push
  2. npm ci
  3. npm run build
  4. wrangler deploy
  5. curl smoke test
  6. live
# .github/workflows/deploy.yml (excerpt)
on:
  push:
    branches: [main]
steps:
  - run: npm ci
  - run: npm run build
  - run: npx wrangler deploy
    env:
      CLOUDFLARE_API_TOKEN: op://ci/cloudflare/token
  - run: curl -fsS https://malena.example | grep -q "Malena"
